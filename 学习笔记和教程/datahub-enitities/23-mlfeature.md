# 机器学习特征

ML Feature（机器学习特征）实体表示机器学习模型所使用的单个输入变量。特征是特征工程的基础构件——它们把原始数据转换为 ML 算法可以学习的、有意义的信号。在现代 ML 系统中，特征是一等公民：可以被发现、记录、版本化，并在多个模型和团队之间复用。

## 标识

ML 特征由两部分信息标识：

- 特征命名空间（namespace）：用于组织相关特征的逻辑分组或命名空间。它通常对应特征表名称、业务域或团队。例如 `user_features`、`transaction_features`、`product_features`。
- 特征名称：特征在其命名空间内的唯一名称。例如 `age`、`lifetime_value`、`days_since_signup`。

一个 ML 特征标识符的示例是 `urn:li:mlFeature:(user_features,age)`。

标识由 `mlFeatureKey` 方面定义，其中包含：

- `featureNamespace`：表示特征逻辑命名空间或分组的字符串
- `name`：特征在该命名空间内的唯一名称

### URN 结构示例

```
urn:li:mlFeature:(user_features,age)
urn:li:mlFeature:(user_features,lifetime_value)
urn:li:mlFeature:(transaction_features,amount_last_7d)
urn:li:mlFeature:(product_features,price)
urn:li:mlFeature:(product_features,category_embedding)
```

命名空间与名称共同构成全局唯一标识。多个特征可以共享同一命名空间（表示一种逻辑分组），但每个特征名称在其命名空间内必须唯一。

### 特征属性

ML 特征通过 `mlFeatureProperties` 方面支持完整的元数据。该方面捕获定义一个特征的关键特征：

#### 描述与文档

特征应具有清晰的描述，说明它代表什么、如何计算以及何时使用。良好的特征文档至关重要，因为它可以：

- 帮助数据科学家为模型发现相关特征
- 避免重复创建特征
- 理解特征语义及适用场景
- 促进跨团队的特征复用


**Python SDK：创建带描述的 ML 特征**

```python
# Inlined from /metadata-ingestion/examples/library/mlfeature_create_with_description.py
import os

import datahub.emitter.mce_builder as builder
import datahub.metadata.schema_classes as models
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.emitter.rest_emitter import DatahubRestEmitter

gms_server = os.getenv("DATAHUB_GMS_URL", "http://localhost:8080")
token = os.getenv("DATAHUB_GMS_TOKEN")
emitter = DatahubRestEmitter(gms_server=gms_server, token=token)

feature_urn = builder.make_ml_feature_urn(
    feature_table_name="user_features",
    feature_name="age",
)

metadata_change_proposal = MetadataChangeProposalWrapper(
    entityUrn=feature_urn,
    aspect=models.MLFeaturePropertiesClass(
        description="Age of the user in years, calculated as the difference between current date and birth date. "
        "This feature is commonly used for demographic segmentation and age-based personalization. "
        "Values range from 18-100 for registered users (age verification required).",
        dataType="CONTINUOUS",
    ),
)

emitter.emit(metadata_change_proposal)

```



#### 数据类型

特征通过 `MLFeatureDataType` 指定数据类型，用以描述特征取值的性质。理解数据类型对于正确的特征处理、预处理和模型训练至关重要。DataHub 支持一套丰富的数据类型分类：

**类别型：**

- `NOMINAL`：没有内在顺序的离散取值（例如，国家、产品类别）
- `ORDINAL`：可以排序的离散取值（例如、学历等级、评分）
- `BINARY`：两类取值（例如 is_subscriber、has_clicked）

**数值型：**

- `CONTINUOUS`：实值数值数据（例如身高、价格、温度）
- `COUNT`：非负整数计数（例如购买次数、页面浏览量）
- `INTERVAL`：间距相等的数值数据（例如百分比、分数）

**时间型：**

- `TIME`：基于时间的周期性特征（例如 hour_of_day、day_of_week）

**非结构化：**

- `TEXT`：需要 NLP 处理的文本数据
- `IMAGE`：图像数据
- `VIDEO`：视频数据
- `AUDIO`：音频数据

**结构化：**

- `MAP`：字典或映射结构
- `SEQUENCE`：列表、数组或序列
- `SET`：无序集合
- `BYTE`：二进制编码的复杂对象

**特殊类型：**

- `USELESS`：高基数唯一值且无预测关系（例如随机 ID）
- `UNKNOWN`：类型尚未确定

#### 来源血缘

DataHub 中 ML 特征最强大的能力之一，是通过 `sources` 属性声明来源数据集。这会在特征与其计算所依赖的上游数据集之间建立明确的 "DerivedFrom" 血缘关系。

来源血缘带来以下能力：

- **端到端可追溯**：将模型预测回溯到生成其特征的原始数据
- **影响分析**：在数据集变更时了解哪些特征（以及下游模型）会受到影响
- **数据质量**：当特征取值出现异常时定位根因
- **合规**：为监管要求记录数据来源
- **发现**：找出所有派生自某个特定数据集的特征


**Python SDK：为特征添加来源血缘**

```python
# Inlined from /metadata-ingestion/examples/library/mlfeature_add_source_lineage.py
import datahub.emitter.mce_builder as builder
import datahub.metadata.schema_classes as models
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.emitter.rest_emitter import DatahubRestEmitter

emitter = DatahubRestEmitter(gms_server="http://localhost:8080", extra_headers={})

    feature_table_name="user_features",
    feature_name="days_since_signup",
)

    name="analytics.users",
    platform="snowflake",
    env="PROD",

    entityUrn=feature_urn,

        "calculated as the difference between current date and signup_date. "

        dataType="COUNT",
        sources=[users_table_urn],
    ),
)

emitter.emit(metadata_change_proposal)

```



#### 版本管理

特征通过 `version` 属性支持版本管理。版本信息帮助团队：

- 追踪特征定义或计算方式的破坏性变更
- 在迁移期间保留多个特征版本
- 了解模型是使用哪个特征版本训练的
- 在训练与服务系统之间协调特征发布

### 标签与术语表术语

ML 特征支持标签和术语表术语，用于分类、发现和治理：

- 标签（通过 `globalTags` 方面）提供轻量级分类，例如 PII 标识、特征成熟度等级或业务域
- 术语表术语（通过 `glossaryTerms` 方面）把特征关联到标准化的业务定义和概念

阅读[这篇博客](https://medium.com/datahub-project/tags-and-terms-two-powerful-datahub-features-used-in-two-different-scenarios-b5b4791e892e)，了解何时使用标签、何时使用术语。


**Python SDK：为特征添加标签和术语**

```python
# Inlined from /metadata-ingestion/examples/library/mlfeature_add_tags_terms.py
import datahub.emitter.mce_builder as builder
import datahub.metadata.schema_classes as models
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.emitter.rest_emitter import DatahubRestEmitter
from datahub.ingestion.graph.client import DatahubClientConfig, DataHubGraph

gms_endpoint = "http://localhost:8080"
emitter = DatahubRestEmitter(gms_server=gms_endpoint, extra_headers={})
graph = DataHubGraph(DatahubClientConfig(server=gms_endpoint))

feature_urn = builder.make_ml_feature_urn(
    feature_table_name="user_features",
    feature_name="email_address",
)

current_tags = graph.get_aspect(
    entity_urn=feature_urn, aspect_type=models.GlobalTagsClass
)

tag_to_add = builder.make_tag_urn("PII")
term_to_add = builder.make_term_urn("CustomerData")

if current_tags:
    if tag_to_add not in [tag.tag for tag in current_tags.tags]:
        current_tags.tags.append(models.TagAssociationClass(tag=tag_to_add))
else:
    current_tags = models.GlobalTagsClass(
        tags=[models.TagAssociationClass(tag=tag_to_add)]
    )

emitter.emit(
    MetadataChangeProposalWrapper(
        entityUrn=feature_urn,
        aspect=current_tags,
    )
)

current_terms = graph.get_aspect(
    entity_urn=feature_urn, aspect_type=models.GlossaryTermsClass
)

if current_terms:
    if term_to_add not in [term.urn for term in current_terms.terms]:
        current_terms.terms.append(models.GlossaryTermAssociationClass(urn=term_to_add))
else:
    current_terms = models.GlossaryTermsClass(
        terms=[models.GlossaryTermAssociationClass(urn=term_to_add)],
        auditStamp=models.AuditStampClass(time=0, actor="urn:li:corpuser:datahub"),
    )

emitter.emit(
    MetadataChangeProposalWrapper(
        entityUrn=feature_urn,
        aspect=current_terms,
    )
)

```



### 所有权

特征通过 `ownership` 方面关联所有权。清晰的特征所有权对于以下事项至关重要：

- 知道遇到特征行为问题时该联系谁
- 明确对特征质量与更新的责任
- 管理访问控制与治理
- 协调跨团队的特征变更


**Python SDK：为特征添加所有权**

```python
# Inlined from /metadata-ingestion/examples/library/mlfeature_add_ownership.py
import datahub.emitter.mce_builder as builder
import datahub.metadata.schema_classes as models
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.emitter.rest_emitter import DatahubRestEmitter
from datahub.ingestion.graph.client import DatahubClientConfig, DataHubGraph

gms_endpoint = "http://localhost:8080"
emitter = DatahubRestEmitter(gms_server=gms_endpoint, extra_headers={})
graph = DataHubGraph(DatahubClientConfig(server=gms_endpoint))

feature_urn = builder.make_ml_feature_urn(
    feature_table_name="user_features",
    feature_name="age",
)

owner_to_add = builder.make_user_urn("data_science_team")

current_ownership = graph.get_aspect(
    entity_urn=feature_urn, aspect_type=models.OwnershipClass
)

if current_ownership:
    if owner_to_add not in [owner.owner for owner in current_ownership.owners]:
        current_ownership.owners.append(
            models.OwnerClass(
                owner=owner_to_add,
                type=models.OwnershipTypeClass.DATAOWNER,
            )
        )
else:
    current_ownership = models.OwnershipClass(
        owners=[
            models.OwnerClass(
                owner=owner_to_add,
                type=models.OwnershipTypeClass.DATAOWNER,
            )
        ]
    )

emitter.emit(
    MetadataChangeProposalWrapper(
        entityUrn=feature_urn,
        aspect=current_ownership,
    )
)

```



### 领域与组织

特征可以按领域组织（通过 `domains` 方面），以表示组织结构或功能区域。领域组织帮助团队：

- 通过对相关特征分组来管理大型特征目录
- 对相关特征应用一致的治理策略
- 在组织边界内便于发现
- 按业务单元追踪特征采用情况

## 代码示例

### 创建一个完整的 ML 特征

下面是一个综合性示例，创建一个具备全部核心元数据的特征：


**Python SDK：创建完整的 ML 特征**

```python
# Inlined from /metadata-ingestion/examples/library/mlfeature_create_complete.py
import os

import datahub.emitter.mce_builder as builder
import datahub.metadata.schema_classes as models
from datahub.emitter.mcp import MetadataChangeProposalWrapper
from datahub.emitter.rest_emitter import DatahubRestEmitter

gms_server = os.getenv("DATAHUB_GMS_URL", "http://localhost:8080")
token = os.getenv("DATAHUB_GMS_TOKEN")
emitter = DatahubRestEmitter(gms_server=gms_server, token=token)

feature_urn = builder.make_ml_feature_urn(
    feature_table_name="user_features",
    feature_name="user_engagement_score",
)

source_dataset_urn = builder.make_dataset_urn(
    name="analytics.user_activity",
    platform="snowflake",
    env="PROD",
)

owner_urn = builder.make_user_urn("ml_platform_team")
tag_urn = builder.make_tag_urn("HighValue")
term_urn = builder.make_term_urn("EngagementMetrics")
domain_urn = builder.make_domain_urn("user_analytics")

feature_properties = MetadataChangeProposalWrapper(
    entityUrn=feature_urn,
    aspect=models.MLFeaturePropertiesClass(
        description="Composite engagement score calculated from user activity metrics including "
        "page views, time on site, feature usage, and interaction frequency. "
        "Higher scores indicate more engaged users. Range: 0-100.",
        dataType="CONTINUOUS",
        version=models.VersionTagClass(versionTag="1.0"),
        sources=[source_dataset_urn],
        customProperties={
            "update_frequency": "daily",
            "calculation_method": "weighted_sum",
            "min_value": "0",
            "max_value": "100",
        },
    ),
)

ownership = MetadataChangeProposalWrapper(
    entityUrn=feature_urn,
    aspect=models.OwnershipClass(
        owners=[
            models.OwnerClass(
                owner=owner_urn,
                type=models.OwnershipTypeClass.DATAOWNER,
            )
        ]
    ),
)

tags = MetadataChangeProposalWrapper(
    entityUrn=feature_urn,
    aspect=models.GlobalTagsClass(tags=[models.TagAssociationClass(tag=tag_urn)]),
)

terms = MetadataChangeProposalWrapper(
    entityUrn=feature_urn,
    aspect=models.GlossaryTermsClass(
        terms=[models.GlossaryTermAssociationClass(urn=term_urn)],
        auditStamp=models.AuditStampClass(time=0, actor="urn:li:corpuser:datahub"),
    ),
)

domains = MetadataChangeProposalWrapper(
    entityUrn=feature_urn,
    aspect=models.DomainsClass(domains=[domain_urn]),
)

for mcp in [feature_properties, ownership, tags, terms, domains]:
    emitter.emit(mcp)

```



### 将特征关联到特征表

特征通常被组织到特征表中。虽然特征实体本身并不直接引用其所属的表（该关系是反向的——由表引用特征），但你可以通过关系发现包含它的表：


**Python SDK：查找包含某特征的特征表**

```python
# Inlined from /metadata-ingestion/examples/library/mlfeature_find_table.py
from datahub.ingestion.graph.client import DatahubClientConfig, DataHubGraph
from datahub.ingestion.graph.openapi import RelationshipDirection
from datahub.metadata.urns import MlFeatureUrn

graph = DataHubGraph(DatahubClientConfig(server="http://localhost:8080"))

feature_urn = MlFeatureUrn(
    feature_namespace="user_features",
    name="age",
)

relationships = graph.get_related_entities(
    entity_urn=str(feature_urn),
    relationship_types=["Contains"],
    direction=RelationshipDirection.INCOMING,
)

if relationships:
    feature_table_urns = [rel.urn for rel in relationships]
    print(f"Feature {feature_urn} is contained in tables:")
    for table_urn in feature_table_urns:
        print(f"  - {table_urn}")
else:
    print(f"Feature {feature_urn} is not associated with any feature table")

```

## 集成点

ML 特征与 DataHub 元数据模型中的多个其他实体集成，构成完整的 ML 元数据生态：

### 与数据集的关系

特征通过 `mlFeatureProperties` 中的 `sources` 属性声明其来源数据集。这会创建 "DerivedFrom" 血缘关系：

- 展示哪些原始数据表为每个特征提供输入
- 在数据集变更时支持影响分析
- 提供从数据仓库到模型预测的端到端血缘
- 支持数据质量根因分析

该关系是有方向的：特征指向其来源数据集。多个特征可以派生自同一数据集；如果某个特征通过 join 或 union 计算得到，单个特征也可以派生自多个数据集。

### 与 ML 模型的关系

ML 模型通过 `MLModelProperties` 中的 `mlFeatures` 属性消费特征。这会创建 "Consumes" 血缘关系，展示：

- 每个模型使用了哪些特征
- 哪些模型依赖某个特定特征
- 模型训练与推理的完整输入集合
- 特征变更对下游模型的影响分析

该关系支撑了如下关键用例：

- **特征使用情况追踪**：识别可以弃用的未使用特征
- **模型影响分析**：找出特征变更时受影响的所有模型
- **特征重要性关联**：把模型性能与特征变更关联起来
- **合规文档**：准确展示哪些数据影响了模型决策

### 与 ML 特征表的关系

特征表通过 "Contains" 关系包含 ML 特征。特征表的 `mlFeatures` 属性列出它所包含的特征 URN。这一关系：

- 把特征组织为逻辑分组
- 支持从表到特征以及从特征回到表的导航
- 表示特征存储中的物理或逻辑组织方式
- 帮助发现具有相同特征的相关特征

虽然特征本身不显式保存其所属的表，但可以通过查询传入的 "Contains" 关系来发现它。

### 平台集成

特征通常通过其命名空间或通过相关实体（特征表）与某个平台关联。虽然特征本身的键中没有直接的平台引用，但命名空间通常编码了平台特定的组织方式，而相关的特征表会显式声明其平台。

### GraphQL 解析器

特征可通过 DataHub GraphQL API 的 `MLFeatureType` 类访问。该 GraphQL 接口提供：

- 特征的搜索与发现能力
- 搜索时对特征名称的自动补全
- 特征元数据的批量加载
- 按属性和关系过滤特征

### 事件

ML 特征参与共享的事件（incidents）子系统。可以通过 `raiseIncident` GraphQL mutation（或 Python SDK）在特征上触发事件，通过 `MLFeature` GraphQL 类型的 `incidents` 字段回溯列出这些事件，特征还携带一个汇总的 `incidentsSummary` 方面，该方面会在事件被触发与解决时自动维护。

## 值得注意的例外

### 特征命名空间与特征表

特征键中的 `featureNamespace` 是一个逻辑分组概念，并不一定与特征表一一对应：

- **在许多特征存储中**：命名空间与特征表名称一致。名为 `user_features` 的特征表包含命名空间为 `user_features` 的特征。
- **在某些系统中**：命名空间可能代表更宽泛的业务域或项目，多个特征表共享同一命名空间。
- **最佳实践**：使用与你的特征表组织方式相一致的命名空间命名，以保证清晰度。

采集特征时，确保命名空间取值与对应的特征表名称一致，以便正确建立关系。

### 特征标识与特征表

特征的标识（`featureNamespace` + `name`）独立于任何特征表。这意味着：

- 同一个特征 URN 理论上可以被多个特征表引用（尽管这并不常见）
- 更改某个特征所属的表需要更新该表的元数据，而非特征本身
- 特征可以不属于任何特征表而独立存在（但这会降低可发现性）

大多数特征存储会强制特征与特征表之间的一对一关系，以避免歧义。

### 版本管理策略

特征版本管理有多种可选方式：

**方案 1：在 URN 中体现版本（命名空间或名称）**

```
urn:li:mlFeature:(user_features_v2,age)
urn:li:mlFeature:(user_features,age_v2)
```

- 优点：每个版本是独立实体，拥有各自独立的元数据
- 缺点：版本历史更难追踪；需要手动进行版本管理

**方案 2：在属性中体现版本**

```python
MLFeatureProperties(
    description="User age in years",
    version=VersionTag(versionTag="2.0")
)
```

- 优点：版本历史附着于单一实体；血缘追踪更容易
- 缺点：时点查询更困难；版本变更会修改实体

**建议**：大多数场景下使用 `mlFeatureProperties` 中的 `version` 属性。只有当破坏性变更需要完全独立的实体时（例如将数据类型从连续型改为类别型），才使用带版本的 URN。

### 复合特征与特征工程

复合特征（由其他特征派生而来的特征）可以用两种方式建模：

**方式 1：将中间特征建模为实体**
为每个转换步骤创建显式的特征实体，并在它们之间建立血缘：

```
raw_feature -> transformed_feature -> composite_feature
```

**方式 2：直接来源血缘**
跳过中间特征，把复合特征直接关联到源数据集，并在描述中记录转换方式。

以下情形选择方式 1：

- 中间特征被多个下游特征/模型复用
- 需要显式追踪转换过程以满足治理要求
- 特征工程流水线复杂且包含多个阶段

以下情形选择方式 2：

- 转换简单且一次性的
- 中间特征没有独立价值
- 希望减少元数据实体数量

### 特征漂移与监控

虽然 DataHub 的 ML Feature 实体不包含内建的漂移监控方面，但你可以使用：

- **自定义属性**：存储漂移指标或监控状态
- **标签**：应用 `HIGH_DRIFT_DETECTED` 或 `MONITORING_ENABLED` 之类的标签
- **文档**：通过 `institutionalMemory` 链接到外部监控仪表板
- **外部系统**：与专门的特征监控工具集成，并在特征元数据中引用它们

特征漂移检测通常发生在运行时的特征存储或模型监控系统中，而 DataHub 充当把这些系统链接起来的元数据目录。

### 搜索与发现

特征可以按以下维度搜索：

- 名称（带自动补全）
- 命名空间（部分文本搜索）
- 描述（全文搜索）
- 标签和术语表术语
- 所有者
- 来源数据集（通过血缘）

`name` 字段拥有最高的搜索加权分（8.0），因此特征名是主要的发现机制。请确保特征名具有描述性，并在整个组织内遵循一致的命名约定。
